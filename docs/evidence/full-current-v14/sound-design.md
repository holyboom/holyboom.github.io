## State ownership
DOM section positions plus the existing pinned-assembly interval determine route markers. Gallery/filter/disclosure/font/resize changes remeasure them. The same pure mapping is exported in soundscape-scenes.js and used by the live graph and offline audition. All spectral/mix changes use AudioParam smoothing on existing nodes. The graph still contains thirteen continuous sources, not thirteen new sources per section. No source is recreated when crossing a zone.

The exact assembly progress remains the source of its story. After assembly, voiceProgress belongs only to sound; it never writes visual progress, transforms, selected skills, range inputs or dialogs. One context, separate background/current/resolve buses, unchanged tap bus and ducking. No chapter chime or end-of-page reward loop.

## Input and reading
Trusted native wheel, touch, keyboard and the assembly range produce current. Tiny jitter, navigation jumps, layout shifts, filtering/search and dialog scrolling do not trigger swooshes. Open dialogs/navigation lower the field to a 0.38 focus factor; visible optional reading disclosures use 0.78. Closing them restores the same instrument, not a new track.

## Continuity and limits
Sound remains behind an explicit gesture. Old preferences persist. Muting sound never stops motion. Backgrounded/interrupted audio stops and waits for a fresh gesture after return. No skipped sounds are queued. Later scene-level multipliers range from 0.6 to 1.08, without an unbounded speed-to-volume mapping.

## Evidence
The v13 default instrument is compared at 24 kHz over twelve seconds using the same parameter score. The five forty-second audition files use the production graph and route, identical taps, master gain and compressor, without per-file normalization. These are synthetic gesture scores, not microphone recordings. Automated checks establish finite signals, routing and lifecycle behavior, not pleasantness on a physical phone or a listening-fatigue study.

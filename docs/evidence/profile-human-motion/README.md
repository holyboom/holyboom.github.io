# การแสดงของตัวละครในหน้าโปรไฟล์

เทียบเว็บจริงรุ่น `f4a8bba` กับภาพที่เบราว์เซอร์วาดจากโค้ดรุ่นนี้ ภาพแถวบนเป็นเวอร์ชันเดิม แถวล่างเป็นเวอร์ชันใหม่ คอลัมน์ในฉากวาดและลังเลอ้างตำแหน่งบนเรื่อง ส่วนฉากผสมสกิลอ้างวินาทีที่มองเห็นวงโคจรหลังสกิลเข้าที่

|---|---|---|---|
| วาดแล้วพิจารณา | มือรองยังกดแผ่น ปลายปากกายกก่อนอกเอนถอย กล้องเผื่อที่ให้เห็นศีรษะพร้อมงาน รอยพับตั้งขึ้นเป็นโครงหลังคา | [ภาพเทียบ](draw-desktop-en.webp) | [ภาพเทียบ](draw-mobile-th.webp) |

ฉากวาดเคยตัดศีรษะบางส่วนออกตอนซูม จึงขยายกรอบให้เห็นทั้งผู้วาดกับงานและจบซูมก่อนมุมข้างเริ่มหมุน ฉากลังเลรอบแรกยังคล้ายการค้ำศีรษะค้าง จึงเลื่อนเวลายกมือกลับมาค้ำและเพิ่มการถ่ายน้ำหนัก ระหว่างปรับพบศอกขวาพลิกเร็วเกินไป จึงแก้แนวพับศอกแล้วตรวจท่าระหว่างทางซ้ำ ส่วนฉากผสมสกิลย้ายรอยต่อพ้นหน้าอกเพื่อเปิดช่องให้มองเห็นขอบที่ประกบ หลักเดียวกันใช้กับฉากอื่น เช่น มือหนึ่งตรึงข้อต่อก่อนอีกมือดึงเส้นให้ตึง และแสงยืนยันการเชื่อมหลังชิ้นงานเข้าที่

ใช้เฟรมที่ถอดด้วย FFmpeg เป็นข้อมูลสังเกต แล้วกำกับท่าในระบบ IK และเส้นโค้งเดิมของเว็บไซต์ ภาพมาจาก Chromium บนเดสก์ท็อปและ viewport จำลองมือถือ ความเข้าใจทางอารมณ์ประเมินจากการดูภาพและการเคลื่อนไหว ยังไม่มีการทดสอบกับผู้ชมกลุ่มตัวอย่าง

[คลิปเทียบการวาดและลังเล](before-after.mp4) ใช้ภาพจากเบราว์เซอร์ที่ตำแหน่งเลื่อนตรงกัน ลำดับเฟรมแสดงการเปลี่ยนท่า ส่วนข้อมูลเวลาเรนเดอร์ การย้อนเลื่อน และการซ่อนแท็บอยู่ใน [ผลตรวจเบราว์เซอร์](browser-review.json)

การวัดรอบสุดท้ายใน Chromium บน Linux ที่จำกัด CPU สี่คอร์ ระหว่างเลื่อนช้าในฉากดราม่า ระยะห่างระหว่างเฟรมที่เปอร์เซ็นไทล์ 95 บนจอใหญ่เปลี่ยนจาก 100.1 เป็น 100.0 มิลลิวินาที และบนมือถือจำลองจาก 66.7 เป็น 66.6 มิลลิวินาที ขณะย้อนบนมือถือค่านี้เพิ่มจาก 50.1 เป็น 66.6 มิลลิวินาที จังหวะภาพจึงยังมีข้อจำกัดในเครื่องทดสอบ แม้การใช้พิกัดขอบถุงมือร่วมกันช่วยลดเวลาสร้างผิว และยังให้รูปทรงเดิมทุกจุด [ผลวัดเฉพาะ geometry](glove-timing.json)
